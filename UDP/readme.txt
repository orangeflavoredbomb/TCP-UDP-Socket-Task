======================================================================
Task 2: UDP GBN Client & Server (基于 UDP 的可靠数据传输与拥塞控制)
======================================================================

【1. 运行环境说明】
- 操作系统：Windows / macOS / Linux 均可
- 解释器：Python 3.x (推荐 3.6 及以上版本)
- 依赖库：除 Python 标准库外，本程序引入了数据分析库 Pandas 用于最终的 RTT 统计核算。
  * 运行前请确保已安装：`pip install pandas` (或 `pip3 install pandas`)

【2. 文件结构】
- udpserver.py : 服务端代码。采用无连接的单线程模型，内置了随机丢包与网络延迟抖动模拟器。
- udpclient.py : 客户端代码。包含 GBN 滑动窗口机制、RTT 动态估算、快速重传以及 Pandas 数据汇总功能。
- test.txt     : 待发送的原始文本文件（需用户自行创建，纯英文 ASCII 编码）。
- run_log.txt  : 运行结束后，客户端自动生成的带毫秒级时间戳的传输日志与性能汇总报告。

【3. 配置选项】
▶ 客户端配置 (可在 udpclient.py 中修改)
- server_ip   = '127.0.0.1'  # 服务器 IP 地址（默认本地环回）
- server_port = 8000         # 服务器通信端口
- file_path   = 'test.txt'   # 待传输的目标文件路径
- window_size = 400          # GBN 物理滑动窗口大小 (字节)
- TIMEOUT_SEC = 0.3          # 初始超时时间 (后续将由 EWMA 算法实时动态调整)
- 分块大小     = [40, 80]     # 在代码中由 random.randint(40, 80) 动态控制
- max_retries = 5            # 握手阶段最大重试次数 (防御服务端未开启或网络不通)-

▶ 服务端配置 (可在 udpserver.py 中修改)
- DROP_RATE   = 0.05         # 模拟网络丢包率 (5%)
- 模拟延迟     = [0.02, 0.15] # 模拟 20ms~150ms 真实网络传输波动

【4. 详细运行步骤】
步骤一：环境与文件准备
1. 确保已通过 `pip install pandas` 安装必要库。
2. 确保当前目录下存在名为 `test.txt` 的纯文本文件。

步骤二：启动服务器
打开命令行终端，进入当前代码目录，运行以下命令：
> python udpserver.py <ListenIP> <ListenPort>
  (macOS请输入：python3 udpserver.py <ListenIP> <ListenPort>)
示例: python3 udpserver.py 127.0.0.1 8000
成功启动后，控制台将输出“UDP GBN Server 已启动”，并显示当前的模拟丢包率。

步骤三：启动客户端
另开一个新的命令行终端，运行以下命令启动 Client：
> python udpclient.py <ServerIP> <ServerPort>
  (macOS请输入：python3 udpclient.py <ServerIP> <ServerPort>)
示例: python3 udpclient.py 127.0.0.1 8000
启动后，客户端将完成应用层的学号握手验证并开始 GBN 流水线传输。
* 正常情况：握手成功后，立即开始 GBN 流水线传输，控制台会实时输出动态计算的 Timeout、RTT、重传动作及快速重传日志。
* 异常情况（健壮性设计）：若服务端未启动或端口错误，客户端会在重试 5 次（每次等待 300ms）后，打印致命错误提示并退出，避免形成无限等待的僵尸进程。

步骤四：查看结果
1. 传输完成后，客户端控制台将打印【传输汇总】，包含：传输总用时、有效网络吞吐量、实际发包数、丢包率，以及最大/最小/平均 RTT 统计。
2. 详细的每毫秒协议博弈过程（如收到冗余 ACK 触发快重传等），均已自动保存在当前目录下的 `run_log.txt` 中。

【5. 本实验核心亮点声明】
1. 精准的字节级窗口：打破按“包数”限制的常规思维，实现了完美契合 400 Bytes 的动态滑动窗口。
2. 工业级自适应 RTT 估算：严格应用 TCP 标准的 EWMA 公式（Alpha=0.125, Beta=0.25），实现超时时间的毫秒级动态自适应收缩。
3. 快速重传策略：程序监听冗余 ACK，在达到 3 次重复时瞬间单发重传，极大缩减了死等超时造成的拥塞真空期.
      此外，代码底层同时保留了“单包重传”与“全窗口重传”两套逻辑，可通过切换注释进行拨测，直观验证不同重传策略对链路拥塞及丢包率的放大效应。
4. 客户端双线程异步架构：主线程专职管理发送流水线与超时倒计时，独立子线程阻塞接收 ACK，完美解决了网络 I/O 阻塞与状态机的冲突。
